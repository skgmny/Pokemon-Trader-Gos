## 1. 목적과 기준 문서

Android MVP의 입고·검수·구매·팩 개봉·배송·재매입에서 사용자의 결과와 서버의 실물 재고·잔액 기록이 일치하는지 검증한다. 레어도는 카드에 인쇄된 코드를 사용하고, 물품 거래는 테스트 코인 잔액으로 진행한다. 실제 결제·유료 팩·계좌 출금은 이번 검증 범위에서 제외한다.

- [상세설계서](../03-상세설계/상세설계서.md) · 기능별 흐름과 상태 전환
- [구현·테스트 인계서](../04-구현/구현-테스트-인계서.md) · 후보 빌드와 환경, 남은 제약
- [SRS](../01-요구사항분석/요구사항명세서-SRS.md) · 수용 기준
- [RTM](../01-요구사항분석/요구사항추적매트릭스-RTM.md) · 요구사항과 테스트 연결

## 2. 테스트 전략과 범위

| 구분 | 확인할 내용 | 연결 |
| --- | --- | --- |
| 기능·통합 | 입고 동봉 수량과 검수 후 보류, 감액·반려, 매입과 재매입 적립, 개별 구매 차감, 배송·운송장 조회를 검증한다. | TC-FN-001~005, TC-FN-007~010 |
| 팩과 재고 | 혼합형과 단일 레어도형의 허용 코드, 팩별 가격, 재고 소진과 실물 한 장 배정을 검증한다. | TC-FN-006 |
| 접근 권한·정합성 | 사용자의 정보 조회 범위, 운영자 권한, 동시 요청에서 단일 배정과 잔액·배송 상태를 검증한다. | TC-NF-001~002 |
| Android 접근성 | 360dp와 확대 글꼴에서 상태 라벨, 터치 영역, 필수 정보·오류 문구를 확인한다. | TC-NF-003 |

후보 빌드가 인계되면 설치·접속·기본 조회가 되는지 확인한 뒤 시나리오를 실행한다. 수정 빌드는 영향을 받은 요구사항과 관련 거래를 재검증한다. 부하·응답 시간 목표와 측정 환경은 합의 후 범위를 추가한다.

## 3. 환경과 테스트 데이터

| 항목 | 준비 기준 | 상태 |
| --- | --- | --- |
| Android 후보 | 구현 커밋, APK 식별자, SDK·장치와 앱 설치 방법을 인계한다. | 미등록 |
| 서버·QA 환경 | 서버·저장소 버전, 테스트 접근 경로, 초기화 방법을 인계한다. | 미등록 |
| 계정·권한 | 서로 다른 일반 사용자 두 명과 권한 있는 운영자를 준비한다. 발급 방식은 DEC-006에 따른다. | 미결 |
| 실물·가격표·팩 | 조건 충족·미달, 무표기·하자·반려, 마지막 판매 재고, 혼합형·단일형과 각각의 가격, 품절 사례를 준비한다. | 준비 전 |
| 잔액·배송 | 충분·부족 잔액 계정, 창고 보관 카드, 배송 요청 카드, 테스트 운송장을 준비한다. 실제 물류 검증 범위는 DEC-005에 따른다. | 준비 전 |

동봉 대상 코드와 N, 기준표 금액, 팩 허용 코드와 가격이 미결이면 승인된 별도 테스트 설정으로만 검증한다. 예시값과 운영 설정을 구분하고 테스트 설정을 기록한다. 경합 시나리오는 독립 재고와 잔액으로 다시 실행할 수 있게 준비한다.

## 4. 진입·중단·종료 기준

| 판단 | 기준 |
| --- | --- |
| 진입 | G4 인계에서 후보 버전과 재현 가능한 환경, 테스트 데이터와 권한을 확인한다. 정책 미결이 있는 사례는 테스트 설정과 검증 범위를 먼저 합의한다. |
| 중단·재개 | 설치·접속 실패나 데이터 오염으로 결과를 판단할 수 없으면 해당 항목의 사유를 기록하고 중단한다. 환경·데이터 복구와 영향 범위 확인 후 해당 항목을 다시 실행한다. |
| 종료 | 승인된 범위의 필수 수용 기준을 해당 빌드에서 검증하고 케이스별 결과와 증빙을 연결한다. 출시 차단 결함은 수정 후 재검증하고, 남은 예외는 승인 기록이 필요하다. |

G4, 테스트 일정·담당자와 승인된 종료 기준의 기록은 미결이다. 승인 근거는 [단계별 검토 체크리스트](../08-검토/단계별검토-체크리스트.md#phase-5-테스트-검토)에 연결한다.

## 5. 결과와 결함 기록

[테스트케이스](테스트케이스.md)에서 수행 절차와 기대 결과를 확인하고, [테스트결과보고서](테스트결과보고서.md)에 실제 결과·실행 환경·증빙을 남긴다. 실패 시 TC ID, 후보 빌드, 재현 절차, 기대·실제 결과와 영향 범위를 결함 기록에 연결한다. 중복 배정, 잔액 변경 오류, 권한 위반은 후속 진행 전 영향을 판단한다. 실행 전 항목은 `미실행`으로 기록한다.
