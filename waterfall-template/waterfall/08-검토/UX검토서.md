## 1. 검토 범위와 근거

Android MVP의 마켓·랜덤팩·입고·컬렉션·내 정보와 운영자 흐름을 대상으로 한다. 화면 정보와 상태 표시 기준을 [DESIGN.md](../../../DESIGN.md), [화면설계서](../02-시스템설계/화면설계서.md), [SRS](../01-요구사항분석/요구사항명세서-SRS.md)에서 대조했다. 앱 화면, 기기 동작과 사용자 반응은 후보 빌드가 들어온 뒤 확인한다.

## 2. 화면과 사용자 여정

| 여정 | 문서에서 확인한 설계 | 기기 검증에서 확인할 내용 |
| --- | --- | --- |
| 마켓 → 상세 → 구매 → 컬렉션 | 인쇄 레어도·검수 상태·가격을 따로 표시하고 구매 전 차감액을 안내한다. | 필터의 빈 결과에서 검색을 수정하는지, 구매 후 동일한 재고 번호를 확인할 수 있는지 본다. |
| 혼합형·단일 레어도형 팩 → 개봉 결과 | 팩 유형·포함 코드·가격·장수를 사전에 표시하고 결과에는 실물과 레어도를 표시한다. | 유형과 가격이 구별되는지, 품절 또는 가격 변경 안내가 보이고 개봉 연출을 건너뛰어도 결과를 확인하는지 본다. |
| 입고 신청 → 검수 결과 → 최초 매입 | 필요한 동봉 레어도 코드와 수량, 미확인 레어도, 보류·반려 사유와 제안가를 표시한다. | 부족한 코드를 수정할 수 있는지, 검수 상태와 제안된 금액을 찾고 수락 여부를 구분할 수 있는지 본다. |
| 컬렉션 → 배송·재매입 | 실물 보관과 배송 상태, 운송장, 재매입 제한 사유를 별도 안내한다. | 배송 요청 직후 상태가 갱신되는지, 재매입 제한 이유와 성공 후 잔액 내역을 찾는지 확인한다. |
| 운영 검수 → 재고 배정·출고 | 검수 판정과 레어도, 실물 번호, 배정 및 운송장 필드를 구분한다. | 권한이 있는 담당자가 반려 사유와 배정 가능 범위를 혼동하지 않는지 확인한다. |

## 3. 접근성·예외 검토

| 검토 항목 | 기준 | 실행 상태 |
| --- | --- | --- |
| 레어도와 상태 | 카드에 인쇄된 코드, 검수 결과, 배송 상태를 각각 텍스트로 읽을 수 있다. | 미실행 |
| 글꼴과 터치 | 360dp 폭과 확대 글꼴에서 필수 정보가 보인다. 핵심 조작은 44×44dp 이상이며 오류를 가리지 않는다. | 미실행 |
| 진행·오류 안내 | 처리 중 중복 확정이 제한되고, 응답 누락 시 거래 내역에서 결과를 확인한다. | 미실행 |
| 사진과 검색 | 불러오기 실패 및 빈 검색 결과를 안내하고 수정 또는 재시도 경로를 제공한다. | 미실행 |
| 권한과 개인정보 | 타인의 거래·배송 정보나 제한된 운영 행동을 화면에 노출하지 않는다. | 미실행 |

기기와 Android 버전, 성능 목표 및 접근성 증빙은 미결이다. 디자인 토큰은 문서 기준이며 실제 색 대비, 확대 글꼴, 접근성 이름과 초점 이동은 화면에서 검증한다.

## 4. 결과와 후속 확인

문서에는 정상 경로 및 품절·검수 보류·배송 중 재매입 제한의 화면 상태가 명시돼 있다. 실제 사용성 평가나 결함 판정은 아직 없다. [테스트케이스](../05-테스트/테스트케이스.md)의 TC-FN-001~010과 TC-NF-001·003 중 화면에 해당하는 항목을 실행하고 [테스트결과보고서](../05-테스트/테스트결과보고서.md)에 빌드·기기·결과 및 증빙을 남긴다. UX 검토 담당자, 일정, 승인자는 미지정·미정이다.
