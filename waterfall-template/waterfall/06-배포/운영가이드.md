## 1. 운영 범위와 접근

사용자는 Android 앱에서 카드를 신청·구매·개봉하고 보관 카드의 배송이나 재매입을 요청한다. 운영자는 검수·제안가·재고 배정·출고를 기록한다. 서버가 결과와 테스트 코인 원장을 관리하고 사진 저장소의 접근 범위를 제한한다. [시스템아키텍처설계서](../02-시스템설계/시스템아키텍처설계서-SAD.md) · [상세설계서](../03-상세설계/상세설계서.md)

| 접근 대상 | 필요한 정보 | 상태 |
| --- | --- | --- |
| 운영자 화면 | 접속 경로, 역할별 승인·회수 절차 | 미등록 |
| 서버·데이터·사진 저장소 | 관리 경로, 조회와 변경 권한, 비상 접근 절차 | 미등록 |
| 모니터링·알림 | 대시보드·로그 조회 위치, 알림 수신 및 장애 기록 경로 | 미등록 |

운영자별 필요한 범위의 접근만 부여하고 변경·회수를 기록한다. 자격 증명은 지정된 방식으로 전달한다. 공유 기록에 사진 원본, 주소나 인증 정보를 옮기지 않는다.

## 2. 평상시 운영

1. **입고·검수** · 신청 번호를 기준으로 실물과 등록 레어도를 확인한다. 레어도별 동봉 수량, 판정과 사유를 기록한다. 조건이 깨진 묶음은 보류하고 반려 재고는 배정하지 않는다.
2. **매입·재고 배정** · 기준표와 적용 가능한 예외 가격을 이용해 제안하고 사용자의 수락 여부를 확인한다. 재고 번호를 기준으로 개별 판매 또는 팩에 배정한다. 단일 레어도형은 지정 코드를 사용하며, 혼합형은 허용된 코드만 사용한다.
3. **팩 설정** · 팩별 허용 코드, 테스트 코인 가격과 재고를 대조한다. 소진 시 판매 조건은 확정된 정책을 적용한다. 허용 재고가 없으면 다른 코드로 채우지 않는다.
4. **배송·재매입** · 재고 번호와 요청 상태를 확인하고 승인된 범위에서 출고 정보와 운송장을 기록한다. 배송 요청과 재매입은 하나의 실물에서 함께 확정되지 않아야 한다.

동봉 기준, 하자·반송 처리, 팩 구성·가격, 실제 물류·계정 범위는 [서비스기획서의 미결 결정](../00-기획/서비스기획서.md#7-다음-단계와-미결-결정)에 연결한다.

## 3. 운영 점검과 관측

| 관측 항목 | 확인할 내용 |
| --- | --- |
| 요청 상태·오류 | 앱·서버 버전, 성공·실패 추이, 결과 미확인 또는 품절 오류의 발생 구간 |
| 거래·잔액 | 거래 번호나 요청 키로 처리 결과 조회, 원장의 중복 적립·차감 여부와 소유권 일치 여부 |
| 실물 재고·팩 | 동일 재고의 이중 배정, 반려 카드 노출, 허용 코드 불일치, 개봉 가능 재고와 표시 상태 |
| 배송·권한 | 배송·재매입의 충돌, 출고 정보 누락, 승인되지 않은 조회·처리 여부 |

배포 후 안정화 구간, 점검 주기, 알림 기준과 연락 책임자는 미정이다. 지표 도구가 결정되면 관측 위치와 재현 가능한 조회 방법을 기록한다.

## 4. 장애 대응

1. 최초 발견 시각, 앱·서버 버전, 증상과 영향 범위를 기록한다. 입고 번호·재고 번호·거래 번호 또는 요청 키로 관련 기록을 연결한다.
2. 데이터 노출이나 잘못된 배정·정산이 계속되면 담당자가 영향 작업을 제한한다. 사용자에게 이미 확정된 결과가 있는지 서버 기록으로 확인한다.
3. 변경 승인과 근거를 남겨 복구한다. 영향 범위의 재고·소유권·배송과 잔액을 대조하고, 재현 조건에서 복구 확인 후 작업을 다시 허용한다.

| 장애 | 우선 대응 | 복구 확인 |
| --- | --- | --- |
| 차감 뒤 앱 응답 없음 | 원래 거래의 요청 키와 거래 번호로 서버 결과를 확인한다. 새로운 요청 키로 다시 거래를 만들기 전에 원거래 상태를 확인한다. | 같은 요청에 대해 재고 배정과 잔액 내역이 한 번만 확정됐다. |
| 잘못된 레어도·중복 실물·반려 카드 배정 | 해당 팩 또는 매물의 신규 확정을 제한하고 선택된 재고 번호, 검수 기록과 팩 허용 코드를 대조한다. | 잘못된 후보가 제거되고 승인된 조정 내용과 기존 거래의 결과가 일치한다. |
| 배송과 재매입 결과 상충 | 해당 재고의 출고를 중단하고 현재 소유자·배송 상태·재매입 원장을 확인한다. | 확정 결과와 상태가 하나로 일치하고 추가 출고나 적립이 없음을 확인한다. |
| 타인 거래·배송 정보 노출 | 영향을 받는 접근을 제한하고 요청 시각, 역할과 영향 범위를 확인한다. | 권한 없는 조회에서 정보가 반환되지 않고 인가된 조회는 정상이다. |
| 배포 후 다수 요청 실패 | 새 배포 확대를 중단하고 현재 앱·서버·DB 버전과 오류를 비교한다. | 호환되는 버전으로 복귀하거나 수정한 뒤 핵심 거래와 권한 검증이 재현된다. |

장애 기록에는 담당 역할과 실제 담당자, 조치 시각, 판단 근거와 재검증 결과를 추가한다. 담당자와 연락 경로는 미지정이다.

## 5. 백업과 복구

- 복구 대상은 DB의 재고·소유권·거래·원장·배송 상태와 증빙 사진이다. 백업 일정, 보존 기간, 복구 목표와 담당자는 미결이다.
- 검증 환경에서 DB와 사진 참조의 복구를 확인한 뒤 운영 데이터를 대상으로 한다. 실제 장애에서는 대상 환경과 복구 지점, 현재 상태를 보존할 방법을 확인한다.
- 복구 후 누락되거나 중복된 거래, 잘못된 실물 배정, 마이너스 테스트 잔액, 배송·재매입 충돌을 점검한다. 복구 지점 이후의 확정 거래는 승인된 처리 내역과 대조한다.
