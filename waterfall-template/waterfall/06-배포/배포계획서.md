## 1. 배포 개요

Android 앱과 서버가 실물 카드 입고·검수, 개별 구매, 혼합형·단일 레어도형 팩, 보관·배송 요청·재매입을 테스트 코인으로 처리하는 첫 버전을 대상으로 한다. 실제 결제·현금 결제형 랜덤팩·계좌 출금은 범위에서 제외한다. 실제 택배 처리 범위는 DEC-005에 따른다.

현재 [구현·테스트 인계서](../04-구현/구현-테스트-인계서.md)에 후보 빌드와 환경이 등록되지 않았고, [테스트결과보고서](../05-테스트/테스트결과보고서.md)의 13개 사례는 모두 미실행이다. 배포 후보와 G5 승인 근거가 등록될 때까지 배포 가능 여부는 미결이다.

## 3. 배포 절차

### 3.1 배포 전 확인

1. G5 승인 기록과 후보 아티팩트·서버 버전이 일치하는지 확인한다. 필수 테스트 결과와 허용된 예외를 확인한다.
2. 검증 환경에서 앱과 API의 호환성을 확인한다. 검증용 데이터와 운영 데이터의 범위를 확인하고 운영 정책과 예시값을 구분한다.
3. 데이터 변경이 있으면 검증 환경에서 마이그레이션 및 기존·신규 앱의 호환성을 확인한다. 대상 환경의 백업과 복구 지점을 기록한다.
4. 배포 승인을 받을 때 앱·서버 배포 순서, 롤백 담당자, 배포 후 확인 항목과 공지 여부를 확정한다.

### 3.2 배포 단계

1. 승인된 버전과 변경 기록을 대조하고, 데이터 변경이 있는 경우 승인된 순서로 적용한다.
2. 앱·서버 호환성을 유지하는 순서로 검증한 버전을 배포한다. Android 배포 채널과 실행 명령은 선택한 환경에서 확인 후 기록한다.
3. 각 단계의 실제 버전과 결과를 기록한다. 예상과 다르면 다음 단계로 넘어가기 전에 [운영가이드](운영가이드.md)의 장애 대응 절차를 적용한다.

### 3.4 배포 결과 기록

실제 시작·종료 시각과 적용 버전, 변경 적용 결과, 실패 항목과 재확인 근거를 기록한다. 점검 중 거래에 영향을 주는 문제가 발견되면 배포를 마감하기 전에 4절에 따라 처리 결과를 남긴다.

## 4. 중단과 롤백

- 버전 불일치가 있거나, 타인 정보 노출, 실물 중복 배정, 검수 반려 재고 노출, 중복 차감·적립, 배송·재매입 동시 확정이 관찰되면 배포 확대를 중단한다. 담당자는 제공되는 제어 수단으로 영향 범위의 거래 확정을 제한하고 버전·거래 번호·재고 번호를 기록한다.
- 서버 이전 버전과 현재 DB 구조의 호환성이 확인되면 검증한 버전으로 복귀할 수 있다. 앱 배포 중단과 수정 버전 배포 방법은 선택한 채널에서 확인한다. 이미 설치한 앱과의 API 호환성을 재확인한다.
- DB를 복구해야 하면 먼저 현재 상태를 보존한다. 복구 지점 이후 확정된 거래·재고·원장·배송 기록을 대조하고 재반영 또는 조정 계획을 검토한 뒤 복구한다. 마지막 재고, 배송·재매입 충돌과 중복 처리 여부를 다시 검증한다.

## 5. 일정과 승인 기록

배포 일정, 승인자, 롤백·운영 담당과 복구 시간 목표는 미지정 또는 미정이다. 실제 배포 판단과 운영 인수 근거는 [단계별 검토 체크리스트](../08-검토/단계별검토-체크리스트.md#65-g6-운영-인수)에 기록한다. [운영가이드](운영가이드.md)에서 배포 후 확인과 장애 대응을 이어간다.
