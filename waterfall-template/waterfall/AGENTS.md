# Codex용 워터폴 산출물 작업 지침

Codex는 이 폴더의 워터폴 템플릿으로 프로젝트 산출물을 작성하거나 검토할 때 이 지침을 따른다. [README.md](README.md)에서 단계별 템플릿을 선택하고, 형식이나 작성 예시가 더 필요하면 [워터폴 산출물 예제집](CLAUDE.md)의 해당 절을 참고한다.

## 산출물 작성

- 요청한 산출물과 현재 프로젝트 단계를 확인한다. 사용자와 합의한 범위, 정책, 기존 문서, 구현 및 테스트 기록을 근거로 작성한다.
- 개별 템플릿을 출발점으로 삼고, 프로젝트 규모와 위험에 맞는 항목을 사용한다. 문서를 통합하거나 기존 이슈·PR·CI 기록을 활용하면 해당 자료의 위치를 검토 기록에 남긴다.
- 예시 기능, 기술 스택, 수치, 일정, 승인 및 테스트 결과는 확인된 정보로 바꾼다. 확인이 필요한 항목은 `미결`로 표시하고 확인할 내용, 담당자와 기한을 남긴다. 담당자나 기한도 확인이 필요하면 그 상태를 함께 표시한다. 적용하지 않는 항목은 `해당 없음`과 사유를 기록한다.
- 문서 ID와 파일명은 프로젝트에서 정한 방식을 따른다. 링크와 다이어그램은 실제 문서 위치와 프로젝트 구조에 맞춘다.

## 단계별 기준

| 단계 | 주요 산출물과 다음 단계에 전달할 내용 |
| --- | --- |
| 00 기획 | 서비스 기획서와 비즈니스 정책서에 사용자 문제와 근거, MVP 포함·제외 범위, 핵심 정책과 성공 기준을 기록한다. |
| 01 요구사항 분석 | SRS에 검증 가능한 요구사항과 수용 기준을 적고, RTM에 기획·정책 근거를 연결한다. 흐름이나 예외가 복잡한 경우 유스케이스를 작성한다. |
| 02 시스템 설계 | 아키텍처와 해당하는 DB·API·화면 설계에 시스템 경계, 핵심 결정, 관련 요구사항을 기록한다. |
| 03 상세 설계 | 구현 단위별 처리 흐름, 상태, 예외와 개발 환경을 명시한다. |
| 04 구현 | 구현·테스트 인계서에 검증할 커밋이나 빌드, 실행 환경, 변경 범위, 통과한 점검과 남은 제약을 기록한다. |
| 05 테스트 | 테스트 계획과 케이스를 수용 기준에 연결한다. 결과 보고서에는 실행한 빌드와 환경, 결과 증빙, 종료 기준 충족 여부와 배포 판단을 기록한다. |
| 06 배포 | 배포 계획과 운영 가이드에 배포 버전, 배포 후 점검 결과, 운영 인수와 복구 담당을 남긴다. |
| 07 유지보수 | 변경 요청, 장애와 복구 이력, 다음 릴리스 및 운영 기록을 관리한다. |
| 08 공통 검토 | 단계별 검토 체크리스트와 프로젝트 관리 산출물에 승인 근거, 위험, 의사결정과 변경 이력을 남긴다. |

## 검토와 변경 관리

- RTM에서 MVP 범위와 개별 정책을 요구사항 ID에 연결하고, 단계에 따라 설계·구현·테스트 케이스와 실행 결과를 추가한다. 사업 성공 지표와 요구사항의 수용 기준은 각각 판단 목적에 맞게 작성한다.
- G0~G6 단계 전환을 검토할 때 [단계별 검토 체크리스트](08-검토/단계별검토-체크리스트.md)에 대상 버전, 검토 결과, 승인자, 날짜와 판단 근거를 남긴다. 실제 승인이나 실행 결과가 확인될 때 해당 상태를 기록한다.
- 승인 이후 범위나 정책이 바뀌면 [프로젝트 관리 산출물](08-검토/프로젝트관리-산출물.md)의 변경 관리 계획을 참고해 영향 범위를 검토한다. 관련 SRS, RTM, 설계 및 검증 항목을 함께 갱신한다.
