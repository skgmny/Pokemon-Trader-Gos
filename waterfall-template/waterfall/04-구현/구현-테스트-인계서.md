현재 작업 폴더에서 기획·설계 문서를 확인했다. Android 앱 소스, Gradle 설정이나 래퍼, 서버 프로젝트 진입 파일과 검증용 빌드는 확인되지 않았다. [문서 기준 GitHub 커밋](https://github.com/skgmny/Pokemon-Trader-Gos/commit/901bff80f3745af922dfd506fd11a9f4bee780fa)은 레어도 기준과 설계를 확인하는 참조다. QA에는 별도의 구현 커밋과 빌드를 연결해야 한다.

## 1. 구현 범위

아래 항목은 구현·검증 예정 범위다. 구현 위치와 PR은 미등록이며, 구현 버전을 확인한 뒤 [RTM](../01-요구사항분석/요구사항추적매트릭스-RTM.md)에 연결한다.

| 요구사항 | 상세 설계 | 확인할 동작 | 구현 상태 |
| --- | --- | --- | --- |
| FR-001~003 | DDS-01~02 | 코드별 동봉 신청, 실물 검수, 감액·반려, 최초 매입 수락과 1회 적립 | 미착수 |
| FR-004~005 | DDS-03 | 매물 검색 및 실물 상태 확인, 개별 구매와 컬렉션 반영 | 미착수 |
| FR-006 | DDS-04 | 혼합형·단일 레어도형 팩의 포함 코드, 팩별 테스트 코인 차감과 결과 확인 | 미착수 |
| FR-007~008 | DDS-05 | 컬렉션과 배송 요청, 운송장 조회, 보관 중인 카드 재매입 | 미착수 |
| FR-009 | DDS-06 | 테스트 잔액 원장·거래 내역 조회와 응답 누락 시 결과 확인 | 미착수 |
| FR-010 | DDS-07 | 권한 있는 운영자의 입고·검수 조회, 재고 배정, 출고 처리 | 미착수 |
| NFR-001~003 | 상세설계서 3·6절 | 자원 접근 통제, 재고 및 잔액 정합성, Android 접근성 | 미착수 |

첫 버전은 테스트 코인으로 거래 흐름을 검증한다. 실제 결제·유료 랜덤팩·계좌 출금은 MVP 범위에서 제외한다.

## 2. 빌드와 테스트 환경

| 항목 | 현재 상태 | QA 인계 시 제공할 정보 |
| --- | --- | --- |
| Android 빌드·실행 | 미결 | 소스 커밋, 빌드 명령과 설정, SDK·빌드 도구 버전, APK 식별자, 대상 기기 또는 에뮬레이터 |
| 서버·저장소 | 미결 | 서버 버전과 QA 접속 경로, DB·사진 저장소 환경, 초기화 및 복구 절차 |
| 접근·테스트 계정 | 미결 · DEC-006 | 일반 사용자 두 명과 운영자 권한으로 시나리오를 실행할 수 있는 접근 절차. 접속 정보는 지정된 방식으로 전달한다. |
| 테스트 데이터 | 준비 전 | 레어도 코드별 동봉 충족·미달, 무표기·미확인과 검수 반려, 코드가 다른 두 유형의 팩, 소진 직전 재고, 보관·배송 상태별 카드와 테스트 코인 잔액 |
| 물류 검증 | 미결 · DEC-005 | 테스트 운송장 또는 실제 입고·출고 검증 범위와 결과 확인 위치 |

테스트 데이터의 동봉 장수·레어도 조합과 팩별 가격에는 예시 여부를 표시한다. 운영 정책은 [서비스기획서의 미결 결정](../00-기획/서비스기획서.md#7-다음-단계와-미결-결정)이 확정되면 반영한다.

## 3. 구현 점검 결과와 검증 예정 항목

| 점검 | 결과 | 근거 |
| --- | --- | --- |
| 작업 폴더의 구현 자료 확인 | 기획·설계 문서 확인 | Android 앱, 빌드 설정, 서버 프로젝트 진입 파일과 검증 환경이 확인되지 않았다. |
| 빌드·코드 검토 | 미실행 | 대상 소스·커밋·빌드 및 코드 리뷰 기록 미등록 |
| 단위·통합 테스트 | 미실행 | 테스트 대상 빌드와 실행 환경 미등록 |
| 주요 흐름·Android 접근성 검증 | 미실행 | 후보 앱·기기와 증빙 미등록 |

| 검증 예정 ID | 확인할 결과 |
| --- | --- |
| TC-FN-001~003 | 동봉 수량 N과 N+1 경계, 미확인 코드의 수량 제외, 검수 후 조건 미달 보류, 반려 카드 판매·팩 제외, 최초 매입의 1회 적립 |
| TC-FN-004~006 | 개별 구매의 소유권·차감, 혼합형·단일형의 허용 레어도와 팩별 코인 가격, 허용 재고 부족 시 미차감 |
| TC-FN-007~010 | 배송 상태와 운송장, 재매입 소유권 이전과 적립, 응답 누락 시 내역 복구, 운영자 처리 결과 |
| TC-NF-001~003 | 접근 권한 제한, 동시 구매·개봉의 이중 배정 차단, 배송·재매입 충돌과 중복 정산 차단, Android 화면 접근성 |

세부 시나리오는 [RTM 검증 예정 시나리오](../01-요구사항분석/요구사항추적매트릭스-RTM.md#5-검증-예정-시나리오)를 따른다. 구현 점검과 별도로 QA 실행 결과는 [테스트 결과 보고서](../05-테스트/테스트결과보고서.md)에 후보 빌드와 증빙을 연결한다.

| 남은 결정·제약 | 영향 | 담당자·후속 기한 |
| --- | --- | --- |
| 구현 커밋·빌드·QA 환경과 접근 정보 | G4 인계 및 모든 검증 실행 | 미지정 · 미정 |
| DEC-001~003 · 코드별 동봉 조건, 가격표와 하자·반려 처리 | 입고, 검수, 매입·재매입 및 재고 배정 | 미지정 · 미정 |
| DEC-004 · 팩별 코인 가격, 허용 레어도·수량과 일부 소진 조건 | 혼합형·단일 레어도형 팩 검증 | 미지정 · 미정 |
| DEC-005~006 · 실제 배송 범위와 계정 방식 | 배송, 운영자 권한, QA 접근 | 미지정 · 미정 |

## 4. G4 테스트 인계 확인

- [ ] 후보 커밋과 빌드, 재현 가능한 실행 방법 및 QA 환경을 연결했다.
- [ ] RTM에 실제 구현 위치와 테스트 케이스를 연결했다.
- [ ] 코드 리뷰와 구현 점검 결과, 남은 제약과 담당자를 기록했다.
- [ ] QA 인수자가 환경 접근과 테스트 데이터를 확인했다.
- [ ] [테스트 계획서](../05-테스트/테스트계획서.md)의 진입 기준과 [G4 체크리스트](../08-검토/단계별검토-체크리스트.md#45-g4-테스트-인계)를 충족했다.
