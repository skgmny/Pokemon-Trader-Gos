## 1. 범위와 시작 조건

Android 앱, 운영자 화면, API, 관계형 저장소와 사진 저장소를 대상으로 한다. 유지보수에서는 실물 재고 번호, 소유권, 배송 상태와 테스트 코인 원장의 일치를 우선한다. 실제 결제, 유료 랜덤팩과 계좌 출금은 Android MVP 범위에서 제외한다.

[배포계획서의 G6 운영 인수 기록](../06-배포/배포계획서.md#35-g6-운영-인수-기록)에 운영 버전, 배포 후 점검 근거, 운영 권한과 복구 책임을 등록한 뒤 운영을 인수한다. 현재 배포 및 테스트 실행 기록은 없다. [운영가이드](../06-배포/운영가이드.md) · [테스트결과보고서](../05-테스트/테스트결과보고서.md)

| 작업 유형 | 예시 |
| --- | --- |
| 결함 수정 | 이중 배정, 중복 차감·적립, 검수 반려 카드 노출, 배송·재매입 충돌 수정 |
| 환경 변경 | Android 대상 버전, 서버 또는 저장소 설정 변경 시 호환성과 복구 가능 여부 검증 |
| 정책 변경 | 레어도별 동봉 기준, 매입가 표와 예외, 혼합형·단일 레어도형의 재고 구성과 테스트 코인 가격 변경 |
| 예방 점검 | 권한, 요청 오류, 재고·잔액 정합성, 백업과 복구 절차 점검 |

## 2. 장애 접수와 복구

| 대응 우선순위 | 판단할 상황 | 첫 조치 |
| --- | --- | --- |
| 즉시 확인 | 타인 정보 노출, 잘못된 레어도·반려 카드 배정, 중복 배정·정산 또는 배송·재매입 동시 확정 | 담당자가 영향을 받는 조회나 거래 확정을 제한하고, 요청 키·거래 번호·재고 번호로 확정 내역을 확인한다. |
| 우선 점검 | 입고·구매·개봉·출고의 반복 실패 또는 결과 미확인 | 실패가 집중된 앱·서버 버전과 구간을 파악하고 확정 여부를 조회한다. 기존 요청을 확인하기 전에 새 거래를 만들지 않도록 안내한다. |
| 정기 검토 | 화면 안내, 운영 화면 정렬, 기록 가독성 등 거래 무결성에 직접 영향이 없는 개선 | 재현 내용과 사용자 영향을 기록하고 다음 릴리스 범위를 검토한다. |

장애 기록에는 발견 시각, 환경과 버전, 영향 범위, 조치 담당자·시각, 복구 전후 증빙 및 남은 후속 작업을 기록한다. 공유 기록에 주소나 자격 증명은 남기지 않는다.

DB나 사진 복구가 필요하면 현재 상태를 보존하고 [운영가이드의 백업과 복구](../06-배포/운영가이드.md#5-백업과-복구) 절차를 따른다. 복구 지점 이후 확정된 거래와 실물 상태·원장을 대조한다. 영향을 받은 경로의 재검증과 복구 판단을 기록한 후 작업을 재개한다. 장애 등급별 응답·복구 목표, 당직과 연락 경로는 운영 인수 시 확정한다.

## 3. 변경 요청과 다음 릴리스

1. **접수** · 변경 요청 ID, 사유와 재현 근거, 대상 버전·사용자, 영향을 받는 요구사항 ID와 정책 ID를 기록한다.
2. **영향 검토** · 기존 입고 신청과 유효한 매입 제안, 판매·팩 재고, 재매입 및 배송 요청, 테스트 코인 내역이 영향을 받는지 확인한다. 바뀌는 정책의 적용 시점과 진행 중인 거래의 처리 방식을 승인 기록에 남긴다.
3. **승인과 구현** · 승인된 범위를 관련 정책서·SRS·RTM·설계에 연결한다. 작업 위치, 후보 앱·서버 버전 및 데이터 변경을 기록한다. 긴급 조치도 변경 근거와 후속 검증을 남긴다.
4. **재검증과 배포** · 변경 경로와 관련 회귀 항목을 검증하고 [테스트결과보고서](../05-테스트/테스트결과보고서.md)에 실행 증빙을 연결한다. 적용 순서, 호환성 및 복구 방법은 [배포계획서](../06-배포/배포계획서.md) 기준으로 확인한다.
5. **종료** · 실제 배포 버전과 점검 결과, 운영 이슈와 담당자를 기록한다. 다음 릴리스는 승인된 변경부터 묶어 범위와 일정을 확정한다.

변경 기록 형식은 [프로젝트 관리 산출물](../08-검토/프로젝트관리-산출물.md)을 참고한다. 다음 릴리스 일정과 포함 항목은 미정이다.
